# spec 041 — AI 엔진 고르기 (전사·요약·해석 작업별 모델 선택) · 🧪 1단계 구현

> 상태: **기획 초안 (2026-11-14).** 대표 지시: "너무 낮은 수준의 LLM api보다 품질을 높일 수 있는 방향으로 선택할 수 있게.
> Signal에 여러 LLM api를 등록해 골라 쓰게 만들어 놨으니 참고해서 필요한 부분 적용. EO의 AI 기능 강화도 계속."
> 참고: Signal `lib/ai/{catalog,index,keys,providers,usage}.ts` (읽기 대조 2026-11-14).

## 0. 현황 — Carelog는 모델이 코드에 박혀 있다

| 작업 | 지금 쓰는 것 | 위치 |
|---|---|---|
| 녹음 전사(상담 종료 후) | OpenAI **whisper-1** (2023년 모델) | `app/actions/transcribe.ts` |
| 실시간 전사(통역 PoC) | OpenAI Realtime + gpt-4o-transcribe | `app/api/realtime/token` |
| 상담 요약·상세·용어 보정·다국어 | Claude Sonnet 4.6 고정 | `transcribe.ts` |
| 통역 번역 | Claude Haiku 4.5 고정 | `interpret.ts` |
| 환자용 안내 초안 · 상담 품질 평가 | Claude Sonnet 4.6 고정 | `patient-shares.ts` · `consult-eval.ts` |

문제: ① 더 좋은 모델이 나와도 코드를 고쳐야 바뀐다 ② 한 곳이 막히면(장애·한도) 그 기능이 멈춘다 — 예비가 없다
③ 호출별 실제 모델·토큰·비용이 크레딧 원장과 따로 논다(크레딧 = 고정 단가) ④ 전사 품질 비교 수단이 없다.

## 1. Signal에서 가져올 것 / 바꿀 것

| Signal | Carelog 적용 |
|---|---|
| 회사·모델 목록(단가 포함) 한 파일 | ✅ 그대로 — `lib/ai/catalog.ts`. **전사(음성→글) 엔진도 목록에 포함**(Signal엔 없음) |
| 작업별 순서(1순위 → 2순위 → 3순위) | ✅ 그대로 — 작업마다 최대 3단계 |
| 실패·한도면 다음 모델로, 한도 걸린 모델은 풀릴 때까지 건너뜀 | ✅ 그대로 |
| 호출마다 사용량 한 줄(작업·회사·모델·토큰·추정 비용·응답 시간·성공) | ✅ 그대로 — 기존 사용량 대시보드(spec 013)에 "모델별" 축 추가 |
| 사용자마다 자기 키(내 키 → 없으면 서비스 키) | ⚠️ 바꿈 — Carelog는 **서비스 키 기본**(병원은 크레딧으로 냄, spec 031). 병원별 자기 키는 나중 선택지 |
| 설정은 사용자 개인 | ⚠️ 바꿈 — **슈퍼어드민이 전체 기본값**, (나중) 워크스페이스별 덮어쓰기 |
| "공개 정보는 Gemini 무료" 추천 | ⛔ 금지 — Carelog 작업은 거의 다 **환자 정보**. 무료 등급(입력이 서비스 개선에 쓰일 수 있음)은 환자 정보 작업에 못 쓰게 막는다 |

## 3. 고르는 기준 — "품질 먼저, 예비는 반드시"

- 기본 추천 = **작업별 1순위는 품질 좋은 모델**, 2순위는 다른 회사(장애 분산), 3순위는 빠르고 싼 모델.
- 환자 정보 작업은 목록에서 **"환자 정보 가능"** 표시가 있는 엔진만 고를 수 있다
  (유료 API · 학습 미사용 약관 · 필요 시 국내 보관 — 솔론 기준표로 확정).
- 전사 엔진 후보(평가 대상): OpenAI 최신 전사 모델(gpt-4o-transcribe 계열 — whisper-1 대체 1순위),
  한국어 특화(리턴제로·네이버 CLOVA Speech — 국내 보관 장점), 글로벌 다국어(Google·Deepgram·ElevenLabs 등).
  ★정확한 모델명·단가는 평가 시점 공식 문서로 확정(목록 파일만 고치면 됨).
- 요약·해석 모델: Claude 최신 세대(Sonnet급 기본, 정교한 작업 Opus급, 가벼운 해석 Haiku급), OpenAI·Google 동급을 예비로.

## 4. 전사 품질 평가 (고르기 전에 재 본다)

- 예미안 실제 상담 녹음 표본(동의받은 것, 10~20건) + **치과 용어 정답지**(치아 번호·보철·재료명·숫자)를 만든다.
- 엔진별로 돌려 **오류율(전체·치과 용어·숫자)** · 속도 · 분당 비용을 표로 → 작업별 1순위 결정.
- 잇몸 기록 말로 입력(spec 040)은 **숫자·치아 번호 정확도**가 핵심 → 별도 표본(“17번 구개측 5 3 5…”)으로 따로 잰다.
- 평가 화면 = 기존 녹음 엔진 실험실(비교 모드)을 확장: 같은 음성을 여러 엔진에 돌려 나란히.

## 5. 화면 (슈퍼어드민 `/admin/ai`)

- **엔진 목록**: 회사별 서비스 키 상태(끝 4자리·시험 버튼) — 키 값은 Vercel 환경변수에만(대표가 직접, 다온에게 보내지 않음).
- **작업별 순서**: 작업마다 1→2→3순위 드롭다운(환자 정보 가능 엔진만 표시) · "추천으로 채우기".
- **사용량·요금**: Signal 화면처럼 기간·작업·모델·회사별 호출·토큰·추정 비용·응답 시간·실패, 최근 호출 기록.
  크레딧(병원에 매기는 값)과 실제 비용(우리가 내는 값)을 나란히 → 크레딧 단가 조정 근거.
- 한도 걸림 목록(언제 풀리는지)·수동 해제.

## 6. 구조

```
lib/ai/catalog.ts    회사·모델(종류: llm|stt|stt_stream, 단가, 환자 정보 가능 여부) · 작업 목록 · 기본/추천 순서
lib/ai/providers.ts  회사별 호출(Anthropic·OpenAI·Google … · 전사 엔진 포함) — 응답에서 실제 모델명·토큰·길이(초) 회수
lib/ai/index.ts      askAI(task, …) / transcribe(task, audio) — 순서대로 시도·한도 건너뛰기·사용량 기록
lib/ai/usage.ts      ai_usage 테이블(호출마다 한 줄) — 크레딧 원장과는 별도(크레딧은 지금처럼 기능 단가)
설정 저장            ai_settings(전체 기본값 1행 + 이후 워크스페이스별)
```
- 기존 코드는 모델 이름을 직접 쓰는 대신 `askAI("summary", …)`·`transcribe("stt_record", …)`로 바꾼다 — 작업 단위로 하나씩.
- 실시간 전사 토큰 발급(`/api/realtime/token`)도 작업 `stt_live`의 1순위 엔진을 따른다.

## 7. EO와의 관계

- EO도 AI 기능을 계속 키우는 중 → 같은 틀(목록·작업별 순서·사용량)을 쓰면 나중에 **EO AI 게이트웨이**(크레딧 게이트웨이 spec 031처럼)로 합칠 수 있다.
  1차는 Carelog 안에서 Signal 구조로 만들고, 합칠지는 헤임달·테오 안건(카드는 1단계 후).

## 8. 단계

| 단계 | 내용 |
|---|---|
| **1** | `lib/ai` 틀 + 사용량 기록 + 기존 요약·초안·평가를 askAI로 이전(동작 동일) · 예비 모델 자동 넘김 |
| 2 | 전사 엔진 목록화 + **품질 평가(§4)** → whisper-1 교체 · `/admin/ai` 작업별 순서 화면 |
| 3 | 실시간 전사 `stt_live` 엔진 선택 — 잇몸 기록 말로 입력(spec 040 2단계)의 기반 |
| 4 | 워크스페이스별 설정·(선택) 병원 자기 키 · EO 게이트웨이 검토 |

## 9. 확인 필요

- 솔론: 환자 정보를 보낼 수 있는 AI·전사 업체 기준(학습 미사용·보관 기간·국외 이전 고지). 엔진 목록의 "환자 정보 가능" 표시는 이 기준으로만 켠다.
- 대표: 새 회사(예: 국내 전사 업체) 계약·키 발급은 대표가 직접.

## 10. 1단계 구현 기록 (2026-11-14)

- `lib/ai/{catalog,index}.ts` — Signal 구조 이식(서비스 키·슈퍼어드민 전체 설정·환자 정보 가능 모델만).
- 기본 순서 = **기존 동작 그대로 + 다른 회사 예비**(요약·초안·평가: Claude Sonnet 4.6 → GPT-6.1 Sol / 통역: Claude Haiku 4.5 → GPT-6 Luna).
  "추천: 품질 우선"(Claude 5.5 세대 1순위)은 `/admin/ai`에서 대표가 눌러 저장하면 적용.

- 사용량: `ai_usage` 호출마다 한 줄(실패 포함) — `/admin/ai`에 작업·모델별 집계·최근 호출. 테이블이 없으면 기록만 건너뜀(동작 무영향).
- migration `20261114000001_ai_routing.sql`. 전사 엔진(whisper-1·실시간)은 2단계.
