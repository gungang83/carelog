# spec 040 — 구강 지표 기록 (치주 차트부터) · 📝 기획 초안

> 상태: **기획 초안 v2 (2026-11-14 — 대표 1차 피드백 반영: 순서 자유·말 입력 문맥·지표 확장).** 대표 요청: 진료실에서 치아·구강 지표를 실시간으로 입력하고 그림에 바로 반영 —
> 환자 상담용으로 시작하되, 나중에 환자의 실제 사진·이미지와 합쳐 보여주는 것까지 염두에 둔다.
> 엔진 재사용·고도화: 치아 도식 2D/3D(spec 037) · 그리기 엔진(spec 039) · 치간칫솔 차트(spec 036) · 환자 포털(spec 038) · 녹음/전사.
> ⚖️ 용어 규칙: 케어로그 산출물 = "상담 기록". 이 기능의 결과물도 **"잇몸 기록(치주 차트)"** — 상담 기록의 일부로 부른다(§9 솔론 확인).

## 0. 왜 Carelog에서

- 진료실에서 지표를 가장 많이 쓰는 순간은 **위생사가 측정하면서 환자에게 설명할 때**다. 지금은 종이 차트·덴트웹 숫자 칸 → 환자는 숫자만 듣는다.
- Carelog는 이미 상담보드·치아 그림(2D/3D)·그리기·환자 전달(문자 링크·포털)을 갖고 있다.
  → **측정하는 순간 그림이 바뀌고, 그 그림이 그대로 상담 기록과 환자 레포트가 되는** 흐름을 만들 수 있다.

## 1. 범위 (대표 요청 정리)

| 묶음 | 내용 |
|---|---|
| A. 치주 차트 입력 | 치아별 B(협측)·P/L(구개·설측) 선택 → 부위별 probing depth 0~12mm, 그 이상은 F(full depth) 또는 13↑ 숫자 |
| A-1. 그림에서 고르기 | 치아에 마우스를 올리면 CEJ 아래로 mm 눈금 숫자가 나오고, 고르면 기록 + **잇몸이 얼마나 내려갔는지 바로 그림에 보임** |
| A-2. 말로 입력(STT) | "#17 palatal 부위 distal 쪽부터 잽시다. 5, 3, 5…" → 실시간 전사 → 해석 미리보기 → [확인] 누르면 치아별로 적용 |
| B. 지표 확장 | 출혈점(BOP), 치은 퇴축(recession, 1~5mm·그 이상), 동요도 (+)~(+++), 그 밖에 계속 추가할 수 있는 구조 |
| C. 환자 레포트 | 치간칫솔 사이즈·지표가 환자에게 잘 전달 · 환자가 스스로 기록도 하는 형태 |
| D. 사진과 합치기 | 기록된 수치·상태를 환자 실제 구강 사진 위에 겹쳐 보이기(나중) |

## 2. 측정 부위 · 순서

- **치아당 6부위**(국제 표준): 협측 D·중앙·M + 구개(상악)/설측(하악) D·중앙·M.
  저장 키 = `FDI 치아번호 · 면(B|L) · 위치(D|C|M)` — 상악 L은 화면에 "P"로 표시.
- ★**순서를 정해 두지 않는다(대표 확정).** 사용자가 마우스를 올리는 치아·면·부위가 곧 입력 위치 — 어느 치아부터, 어느 방향으로든.
- 다만 편의로 "다음 칸" 추천은 둔다: 방금 입력한 위치에서 **그 사람이 진행하던 방향**(예: 17→16→15, D→C→M)을 이어 간다.
  빠른 입력·말 입력이 "다음"으로 넘어갈 때만 쓰이고, 언제든 다른 칸을 누르면 거기서 다시 이어진다.

## 3. 지표 등록부 (확장 구조 — ★다양한 인덱스를 계속 추가할 예정)

> 그리기 엔진의 도구 등록부(spec 039)와 같은 방식: **지표 하나 = 정의 하나**. 입력 화면·그림·저장·요약·환자 레포트가
> 정의를 읽어 동작 → 새 인덱스를 붙여도 다른 곳은 손대지 않는다. 정의는 처음엔 코드, 이후 기공지 양식(spec 035)처럼
> **데이터(DB)로 옮겨 병원이 자기 인덱스를 추가**할 수 있게 한다.

### 3-1. 정의가 담는 것
| 항목 | 예 |
|---|---|
| 기록 단위(level) | 부위(6점) · 면(4면/5면) · 치아 · 치근 이개부 입구 · 6분악(sextant) · 구강 전체 |
| 값 모양 | 정수 범위(0~12 + `F`·`13+`) · 단계(0/+/++/+++) · 있음/없음 · 점수(0~3) · 글 · 사이즈(치간칫솔) |
| 계산 | 다른 값으로 계산(CAL = PD + REC) · 지수 계산(%, 평균, 개수) |
| 그림 | 포켓선 · 잇몸선 · 점(출혈) · 배지(동요) · 면 칠하기(치태) · 삼각형(이개부) · 색 지도 |
| 색·기준 | 값 → 색(예: PD ≤3 초록·4~5 주황·≥6 빨강) — 병원이 조정 가능 |
| 말 입력 단어 | "출혈", "동요 투플러스", "퇴축 2" 등 이 지표를 부르는 말(spec 041 `chart_parse`가 사용) |
| 환자용 설명 | 쉬운 말 이름·설명("잇몸 주머니 깊이") |

|---|---|---|---|

| 치주 | 부착 소실(CAL) = PD + REC (계산값) | 부위 | **1** |

## 4. 데이터

- `oral_exams` — 측정 한 번(= 검사 회차): `id · institution_id · patient_id · consultation_id(선택) · kind('perio'…) ·
  recorded_by · recorded_at · status(draft|done) · data jsonb · summary jsonb · created_at/updated_at`.
  - `data` = 버전 붙은 기록 `{v:1, teeth:{missing,implant}, entries:[{t:"17",s:"L",p:"D",m:"pd",v:5,at,by,src,review,utt}], utterances:[{id,text,at}]}` —
    **한 줄 = 한 부위·한 지표**(음성 적용·되돌리기·지표 추가가 쉬움, 회차 비교도 단순).
    `m` = 지표 등록부의 id(새 지표는 새 id로 그냥 쌓임) · `src` = click|keypad|voice · `review` = 말로 입력·검토 전 ·
    `utt` = 그 값을 만든 전사 문장 id(§5-3).
  - `summary` = 저장 시 계산: 평균 PD · 4mm↑/6mm↑ 부위 수 · BOP% · 동요 치아 수 등(목록·추이 그래프용).
- RLS: enable + 정책 0, 서버 액션(기관 멤버십 가드)만 — 기존 패턴.
- 같은 환자의 여러 회차 → **재평가 비교**(지난번 대비 좋아진 부위 초록·나빠진 부위 빨강).
- 치간칫솔 차트(spec 036)도 지금은 그림+글로만 남는다 → 같은 틀에 `kind:'brush'` 회차로 **구조화 저장** 추가(환자 레포트·추이용, §7).

## 5. 입력 화면

진입: 상담보드 **[🦷 잇몸 기록]**(환자 연결된 상담) · 환자 페이지 **[잇몸 기록 시작]**. 전체화면, 치아 그림(spec 037) 위에서.

### 5-1. 그림에서 고르기 (대표 핵심 요청)
1. **교합면 도식**(2D/3D 전환 그대로)에서 아무 치아 + 면(B/P)에 마우스를 올린다 — 치아 바깥쪽 반원 = B, 안쪽 반원 = P/L. 순서 자유(§2).
2. 옆(또는 아래)에 그 치아의 **정면 도식**이 크게 뜬다. 2D 정면 도식은 이미 **CEJ = 기준선, mm 단위**로 그려져 있어 실제 비율 그대로 그릴 수 있다.
3. 그 면의 D·C·M 위치 아래로 **mm 눈금 숫자 사다리**가 잇몸선 아래부터 뿌리 방향으로 나온다(0~12, 맨 끝 `F`·`13+`).
   마우스를 내리면 해당 깊이까지 포켓이 미리 그려지고, 누르면 기록 → "다음 칸" 추천(진행 방향 이어 가기)으로 이동, 다른 칸을 고르면 거기서부터.
4. 퇴축은 같은 사다리를 **잇몸선 위치 모드**로 — 잇몸선이 CEJ 아래로 내려가는 모습이 바로 보인다.
5. BOP는 부위를 한 번 더 누르거나 [출혈] 토글, 동요도는 치아 메뉴에서.

### 5-2. 빠른 입력 (숫자판·키보드)
- 실제 전악 측정은 168부위 — 그림 고르기만으로는 느리다. 시작 칸을 고르고 **숫자판/키보드로 "5 3 5"** 입력 → 진행 방향대로 다음 칸(§2). `B` = 출혈 표시, `F` = full depth.
- 그림은 입력과 동시에 갱신(5-1과 같은 화면, 입력 방식만 다름).

### 5-3. 말로 입력 (STT)
- [🎙 말로 기록] → 실시간 전사가 화면 위에 흐른다(전사 엔진은 spec 041 `stt_live` — 숫자·치아 번호 정확도로 골라 둔 엔진).
- **문맥을 말로 정한다**: "#17 palatal distal부터 앞쪽으로 적을게요" → 위치 = 17번 · 구개측 · D에서 시작 · 진행 방향 = 앞쪽(17→16→15…, 면 안에서는 D→C→M).
  이후 "5, 3, 5, 4, 3, 4…"는 그 방향으로 차례로 채운다. 중간에 "16번 협측", "출혈", "동요 투플러스", "퇴축 2", "결손"처럼 말하면 그때그때 바꾼다.
  화면에는 **지금 받는 위치(커서)**가 치아 그림 위에 깜박여 보인다.
- 해석: 규칙 기반(숫자·치아 번호·면 이름 — 한국어 "오/다섯", "십칠번/일칠", 협측/구개측/설측/buccal/palatal/lingual) +
  애매한 말은 AI 해석(spec 041 `chart_parse`).
- ★**막지 않고 받아 적는다(대표 확정)**: 말한 값은 바로 차트에 들어가되 **"말로 입력 · 검토 전"** 표시(점선·연한 색)로 남는다.
  잘못 알아들었을 수 있으니 → 나중에 칸을 눌러 고치거나, 전사 문장을 눌러 그 문장이 채운 칸들을 한 번에 보고 고친다.
  [검토 끝]을 누르면 표시가 사라지고 확정.
- **전사 원문은 남긴다**: 이번 잇몸 기록 회차에 문장 단위로 저장(각 값이 어느 문장에서 왔는지 연결) — 고칠 때 근거.
- 상담 녹음과의 관계: (확인 필요 §10-1) 말로 기록을 상담 녹음 중에 하면 같은 음성에서 상담 기록 전사도 이어지게 할지.

## 6. 보여주기 (시각화)

- **치주 차트 보기**(표준 4줄: 상악 협측·구개, 하악 설측·협측) — 2D 정면 도식 줄마다 **잇몸선(분홍)·포켓 바닥선(파랑)**을 mm로 그리고,
  BOP 빨간 점, 동요도·결손 표시, 숫자 칸(기존 종이 차트처럼). 색: PD ≤3 초록 · 4~5 주황 · ≥6 빨강.
- **환자 설명 보기**: 숫자 대신 색 지도(교합면 도식에 치아·부위별 색) + "잇몸이 내려간 정도" 그림 강조.
- **3D**: 치아 목(CEJ) 둘레에 부위별 색 띠 + 잇몸선 높이 표시 → 이후 잇몸 메시 자체를 내리는 표현으로 고도화.
- **회차 비교**: 지난 기록과 나란히·차이만 색.
- [기록에 담기] → 상담 기록에 ① 차트 그림 ② 요약 글(복붙용 — 덴트웹에 옮기기 쉽게) — 치간칫솔 차트와 같은 방식. 구조화 데이터는 `oral_exams`에.
  그림은 그리기 엔진(spec 039)으로 열어 더 그려 설명할 수 있다.

## 7. 환자 레포트 · 스스로 기록

- **환자용 안내(spec 038)에 "내 잇몸 기록" 블록** — 보낼 항목 고르기에서 선택. 숫자표 대신 색 지도·쉬운 말 요약
  ("깊은 곳 6곳 → 지난번 9곳보다 줄었어요"), 내 치간칫솔 사이즈 지도(어디에 어떤 사이즈).
- **포털 "내 구강 기록"**: 받은 레포트 모아 보기 + 추이(회차별 BOP%·깊은 부위 수).
- **스스로 기록**(환자 계정): 하루 체크(양치·치간칫솔 사용·양치할 때 피 남 여부), 불편한 부위 표시(교합면 도식 탭), 사진 첨부(선택).
  → 다음 내원 때 직원 화면에 "환자 기록" 요약. ★환자 기록은 환자 소유 — 병원은 환자가 공유 동의한 것만 본다.
- 넛징: 치간칫솔 사용 리마인드(포털 알림), 재평가 시기 안내.

## 8. 사진과 합치기 (나중 단계)

- 사진 출처: 업로드·촬영, WebCeph 연동(spec 033).
- 맞추기: 사진에서 기준 치아 3~4개를 눌러 위치를 알려주면 치열 도식을 사진에 맞춰 겹친다(정렬 변환) → 색 지도·잇몸선을 사진 위에.
  자동 치아 인식(AI)은 그 다음 고도화.
- 결과는 그리기 엔진 바탕(`base.kind:"image"`) + 겹친 층 → 상담 기록·환자 레포트로 그대로.

## 9. 법·용어 확인 (솔론 — 착수 전)

- 치주 측정값은 임상 수치다. Carelog 기록이 **의무기록(의료법)으로 취급되는지**, "상담 기록"의 일부로 다룰 수 있는지 확인 필요.
  원칙안: 덴트웹(진료 차트)이 정본, Carelog는 **환자 설명·상담용 사본**(복붙 글 제공).
- **자동 진단 금지**: 병기(stage)·등급(grade) 자동 판정 등은 의료기기 소프트웨어 위험 → 1차는 **측정값·그림·계산 수치(CAL·%)만**, 판정 문구 없음.
- 환자 스스로 기록·포털 노출 범위는 spec 038 동의 틀 재사용.

## 10. 결정 현황

- ✅ 측정 순서 고정 안 함 — 사용자가 고르는 칸이 입력 위치, "다음 칸"은 진행 방향을 이어 감(§2)
- ✅ 말 입력 = 문맥 문장으로 시작("#17 palatal distal부터 앞쪽으로") · 일단 받아 적고 나중에 고침 · 전사 원문 보관(§5-3)
- ✅ 동요도·퇴축·치태지수 1단계 포함, 인덱스는 계속 추가 — 등록부 확장 구조(§3)
- ✅ AI·전사 엔진은 품질 우선으로 고를 수 있게 — spec 041
- ⏳ 1. "대화 기록은 시작하되, …" — 말씀이 중간에 끊겼습니다. 말로 기록할 때 **상담 녹음(대화 기록)도 함께 시작**해서
  상담 기록 전사와 잇몸 수치 추출을 같은 음성에서 하자는 뜻인지 확인 필요.
- ⏳ 2. 퇴축 음수(잇몸 증식) 입력 필요 여부
- ⏳ 3. 잇몸 기록을 상담 없이도 따로 시작 가능하게 할지(권고: 가능, 상담 연결은 선택)
