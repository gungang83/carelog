# spec 037 — 치아 도식 라이브러리 (2D SVG · 3D는 조사 단계)

> 상태: **1단계(2D SVG) 구현 (2026-10-22)** · 2단계(3D) **시제품 구현**(자체 모델) — 던디대 모델은 파일 확보 대기 · 3단계(환자 실사진·CBCT 등)는 지금 안 함.
> 대표 지시 (2026-10-22): "앞으로 Carelog에서 두루두루 쓸 전체 구강 이미지를 제대로 만들어놓자. 치아의 해부학적인 모양,
> 교합면·정면·측면을 여러 장 그려 라이브러리로, 각 치아마다 치아 번호도 매칭." → "1단계는 SVG로 직접 그려.
> 필요한 만큼 우리가 수정해서 활용할 수 있도록 잘 보관해놓자. 색깔 등을 바꾸거나 다른 상담자료 만들 때도 계속 활용할거거든.
> 2단계까지(사용 시 2D냐 3D냐 선택). 3D 모델은 웹에 없나? 구매 필요하면 예산 투입 가능 — 일단 조사부터."

## 1. 1단계 — 2D SVG (구현)

| 층 | 경로 | 역할 |
|---|---|---|
| **원본** | `lib/dental/teeth.ts` | 치아 모양(평균 치수 mm로 계산) · 배치(교합면 U자 아치 / 정면) · FDI 유틸 · 문자열 SVG 내보내기. 순수 TS(외부 import 없음) |
| 화면 부품 | `components/dental/dental-teeth.tsx` | `DentalTeeth`(다른 SVG 안에 끼우는 `<g>`) · `DentalArchSvg`(단독). 치아별 색 `paint[FDI]`, 클릭 `onToothClick(fdi)` |
| 보관함 화면 | `/admin/dental` (`components/dental/dental-library.tsx`) | 방향·7-7/8-8·치식 번호·색(치관·치근·윤곽·구) 바꿔 보기, 치아 눌러 강조, **SVG 내려받기**. 슈퍼어드민 전용 |
| 고정 파일 | `public/dental-svg/` | `arch/occlusal|facial-7-7|8-8(-plain).svg` + `occlusal/<FDI>.svg`·`facial/<FDI>.svg`(32개×2). 생성: `node --experimental-strip-types scripts/export-dental-svg.mts` |

- **치식**: FDI(11~48). 화면 = 환자를 마주 본 시점(왼쪽 = 환자 우측). 모든 치아가 `<g data-fdi="16">`(파일은 `id="tooth-16"`도)로 묶여
  일러스트레이터·피그마에서 치아별로 골라 고칠 수 있다.
- **모양**: 외부 그림을 따라 그리지 않았다 — 치아별 평균 치수(근원심·협설·치관·치근 mm)로 윤곽을 계산(Catmull-Rom→베지어).
  교합면: 절치(절단연·설면 결절) · 견치 · 소구치(중심구) · 상악 대구치(사다리꼴·사선 융선 구) · 하악 대구치(5교두 구).
  정면: 치관+치근(대구치 분지, 상악 소구치 홈).
- **배치**: 교합면은 치아 폭 합 = 아치 호 길이(겹침 없음), 접촉점(`gaps`, "17-16")과 바깥 방향 법선 제공 → 치간 표시 등에 사용.
  정면은 원근으로 뒤쪽 치아가 좁아진다.
- **첫 사용처**: 치간칫솔 사이즈 차트(spec 036) — 원형 치아를 해부학적 교합면 도식으로 교체, 범례는 오른쪽 칸(PNG에도 찍힘).
- **다음 후보**: 기공지 치식도(`components/lab/tooth-chart.tsx`), 상담 캔버스 배경, 견적 빌더 부위 표시, 측면(협측) 뷰 추가.

## 2. 2단계 — 3D (조사 완료 · 결정 대기)

조사일 2026-10-22. 요구 = 치아 32개가 따로 떨어져 FDI로 이름 붙은 웹용(GLB) 모델, 상업 SaaS에서 브라우저로 내려보내도 되는 라이선스.

| 후보 | 비용 | 라이선스(웹 SaaS) | 판단 |
|---|---|---|---|
| **직접 제작 의뢰(저작권 양도)** | 견적 필요(전문 의료 시각화 업체면 수천 달러 추정 — 근거 없는 추정, 견적으로 확인) | 우리 소유 — 문제 없음 | ★실서비스 권장. 요구사항(FDI 메시 이름 T11~T48, GLB/Draco, 잇몸 별도, 사랑니 포함)을 계약에 넣는다 |
| BodyParts3D (DBCLS) | 무료 | CC BY-SA 2.1 JP — 상업 가능, 출처 표시 + **동일조건**(고친 모델도 공개해야, 경쟁사가 가져다 써도 못 막음) | 시제품·FDI 매핑 검증용. 치아 28개 개별 파트 확인, 사랑니 없음, CT 기반이라 거칠 수 있음 |

| CGTrader Denthea 세트 | 약 $99 | Royalty Free — 웹앱이면 "추출 방지 조치" 의무 → 판매자 서면 허가 필요 | 품질 좋음(28개 분리), 허가 받으면 후보 |

- **유료 스토어 공통 쟁점**: three.js는 GLB를 브라우저에 그대로 내려받으므로 "최종 사용자가 추출할 수 없어야 한다" 조항(Sketchfab·CGTrader·
  TurboSquid·Fab 공통)과 부딪힌다 → 유료 모델은 **판매자 서면 허가**가 전제.
- **다온 제안**: ① 무료 CC BY 모델(던디대)로 3D 보기 시제품을 먼저 만들어 2D↔3D 전환 UX를 검증 ② 쓸 만하면 실서비스용은 저작권 양도 조건으로
  제작 의뢰(견적 2~3곳). 비용 결정은 대표.
- 출처(조사 원문): sketchfab.com/licenses · cgtrader.com/pages/terms-and-conditions · blog.turbosquid.com/turbosquid-3d-model-license ·

## 2.5 3D 시제품 (2026-10-22 — 대표 지시 "던디대 무료 모델로 3D 시제품 만들어봐")

- **보기**: ★대표 정정(2026-10-22) — 2D/3D 전환은 슈퍼어드민이 아니라 **상담 화면에서 쓸 때마다** 고른다.
  상담보드 본문 아래 **[🦷 치아 그림 (2D·3D)]** → 전체화면(`components/dental/tooth-viewer.tsx`): [2D | 3D] 전환(마지막 선택 기억),
  2D는 교합면/정면, 표시 색 5가지로 치아를 눌러 표시(2D·3D가 같은 표시 공유), [기록에 담기] → 지금 화면 PNG + 텍스트
  (`[치아 표시 — 날짜 · N개]` / `빨강: #16(상악 우측 제1대구치)`). `/admin/dental`은 2D 라이브러리(색 바꾸기·SVG 내려받기) 전용으로 되돌림.
  3D 뷰어 `components/dental/dental-3d.tsx`(three.js, next/dynamic으로 3D를 켤 때만 로드). `components/dental/dental-3d.tsx`(three.js, next/dynamic으로 3D를 켤 때만 로드).
  끌어서 돌리기·확대 · 시점 버튼(정면·우측·좌측·상악 교합면·하악 교합면 — 교합면 시점은 맞은편 아치를 숨김) · 입 벌리기 슬라이더 ·
  치아를 누르면 선택(강조색)·치식 표시.
- **모델 ① Carelog 자체 모델**(`lib/dental/teeth-3d.ts`): 2D 원본의 치수·교합면 윤곽·아치 배치를 그대로 써서 단면을 높이별로 쌓아 만든다
  (치근 → 치경선 → 최대풍융부 → 교합면, 전치는 절단연으로 얇아지고 구치는 교두 굴곡). 외부 저작물 0 — 라이선스 걱정 없음.
  한계: 치근 한 갈래로 단순화, 교합면 세부(구·융선) 없음.
- **모델 ② 던디대 "Permanent Dentition"**(CC BY 4.0): ⏳ **파일 확보 대기** — Sketchfab이 다운로드에 로그인을 요구(API 401)해
  에이전트가 직접 받을 수 없다. 대표가 받아 전달하면 → 치아별 분리(연결 덩어리 단위) → 위치로 FDI 판정 → 메시 이름 `T11~T48` →
  `public/dental-3d/dundee-permanent-dentition.glb`로 넣고 `tooth-viewer.tsx`의 `DUNDEE.ready`를 켠다 → 3D에 [기본 모델 | 정밀 모델] 선택이 나타남.
  출처 표기(CC BY 의무)는 정밀 모델 선택 시 화면 아래에 표시. 대표 회원가입 진행 중(2026-10-22).
- **치간칫솔 차트 3D**(spec 036 §2.6): 같은 뷰어에 치간 점(`buildGapPoints3D` — 2D 배치와 같은 변환, 협측 치경부 1/3) + 지정 색.
- **던디대 모델 보류(2026-10-22)**: Sketchfab이 Epic Games 인수(2021) 후 Epic 계정으로만 가입 → 대표 계정 연동이 막힘. 자체 모델로 진행.
- **대표 피드백 반영(2026-10-22)**: ① 입 벌리기 = 평행 이동 → **턱관절 경첩 회전**(하악 전치에서 뒤 92mm·위 20mm 과두 축, 최대 22°,
  치간 점도 함께 회전) ② **교합면 해부 재구성**(`occlusalAnatomy`): 치아 종류별 교두 위치·높이·구(groove)·융선을 데이터로 두고 높이 필드로
  교합면을 만든다 — 상악 대구치 4교두(근심설측 최대·사선융선·협측구·원심설측구), 하악 제1대구치 5교두(설측 교두 높음·근심/원심협측구·설측구),
  하악 제2대구치 +자 구, 상악 소구치 2교두+삼각구, 하악 제1소구치(협측 우세·횡주융선), 하악 제2소구치 3교두 Y자 구, 견치 교두정+설측융선,
  절치 절단연. 구·와는 정점 음영으로 살짝 어둡게. 한계: 교두 경사·크기는 평균값 근사.
  ③ **치근 갈래**(`rootAnatomy`): 상악 제1·2대구치 3근(근심협측·원심협측·구개근 — 구개근 최장, 설측으로 벌어짐, 제2대구치는 덜 벌어짐),
  하악 제1·2대구치 2근(근심·원심, 협설로 넓적, 원심으로 휨), 하악 제3대구치 2근(모아짐), 상악 제1소구치 2근(협측·구개측, 근첨 쪽 절반에서 분지).
  치근간(root trunk) 아래에서 갈래가 벌어지며 근첨으로 가늘어진다. 그 외는 단근(상악 제3대구치는 융합근으로 단순화).
  ④ **분지부 다듬기**: 치근간을 원뿔로 좁혀 갈래 사이로 스며들게 — 평평한 천장·경계선 없이 V자 골.
- **교합면 해부 데이터 일원화**: `occlusalAnatomy`(교두·구·융선)를 2D 원본(`lib/dental/teeth.ts`)으로 옮겨 2D 도식·3D 모델이 같은 데이터를 쓴다.
  2D 교합면 = 교합면 테이블(변연융선 안쪽, 옅은 음영) · 구(진한 선, 테이블 안에서 끝남) · 소와(중심와·근원심 소와 점) · 삼각융선·사선/횡주융선(옅은 선).
  스타일에 `grooveStroke` 추가(보관함에서 "구(홈)" 색 변경). 편집용 SVG(`public/dental-svg/`) 재생성.
- **스냅샷에 그리기**: 치아 그림 [✏️ 그려서 담기] → 지금 보이는 2D·3D 화면을 찍어 기존 그림 도구(`ImageAnnotator` — 펜·직선·화살표·사각형·텍스트)로 그린 뒤 담기.
  **기공지**: 작성 화면 [🦷 치아 모형에 그리기] → 같은 화면(완료 = "첨부하기") → 손그림 첨부(전송 시 drawing).
  3D 모델 표면에 직접 그리기(돌려도 따라 도는 선)는 후속 후보 — 표면 위 선(레이캐스트) 방식이면 가능, 지우기·텍스트까지는 복잡.
- **외부 모델 규칙**: 어떤 GLB든 메시 이름이 `T11`~`T48`이면 같은 뷰어에서 그대로 동작(선택·색·입 벌리기). 제작 의뢰 시 이 규칙을 요구사항으로.
