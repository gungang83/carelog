# spec 038 — 환자용 상담 안내 보내기 + 포털 초대(주민번호 없는 인증)

> 상태: **1·2단계 구현 (2026-10-25)** — 결정 ⓐ~ⓔ 확정. SQL `20261025000001_patient_share.sql` 실행 후 배포.
> 배경: '환자에게 전송' 현황 분석(2026-10-25 세션 68e) — 주민번호 13자리 웹 입력 인증, 직원용 기록 원문 노출,
> 버튼은 한 건인데 실제는 포털 초대(연결된 기록 전부 노출), 동의 자동 기록, 링크 1회용, 보드 저장 경로 알림 없음.

## 대표 방향 (2026-10-25)

1. 주민등록번호를 꼭 받을 필요가 있나? → **받지 않는 방향**(아래 §1).
2. 직원용 기록이 다 들어갈 필요 없다. **상담이 끝나고 환자용 버전을 만들어 보낸다** — 의료기관이 상담 내용 중 골라서 환자용으로.
3. '환자에게 전송'은 한 건 보기이면서 **케어로그 포털로의 초대**이기도 하다. 환자가 케어로그에서 할 수 있는 것을
   계속 늘릴 것이므로 **포털 진입을 계속 넛징**한다.

## 1. 인증 — 주민번호 없이

- 현재: 링크 → 주민번호 13자리 + 전화번호 입력 → 문자 인증번호. 주민번호는 해시로 대조·저장(`patient_accounts.rrn_hash` = 전 기관 공통 환자 계정 키).
- 문제: 개인정보보호법 제24조의2(주민등록번호 처리 제한) — 법령 근거 없이 처리 불가, 인터넷에서 주민번호 없이 가입할 수 있는 방법 제공 의무.
  의료기관이 진료 목적으로 보유하는 것과 별개로, **Carelog가 환자 웹 인증에 쓰는 근거는 약하다**(솔론 검토 요청 — 다온 이해 기준).
  환자 입장에서도 가장 큰 이탈 지점.
- **변경안**: 소지 인증 2단계 — ① 문자로 받은 링크(토큰) ② **병원에 등록된 번호**로 인증번호(화면엔 `010-****-1234로 인증번호 받기` 버튼 하나, 번호 입력 없음).
  - 링크가 다른 사람에게 전달돼도 등록된 휴대폰이 없으면 못 연다.
  - 환자 계정 키 = **인증된 휴대폰 번호**(+ 이후 구글·카카오 연결). `rrn_hash`는 nullable로 두고 새 계정은 채우지 않는다.
  - 번호 변경·가족 공용폰: 병원이 환자 번호를 고치면 다음 링크부터 새 번호로. 한 번호에 여러 환자(가족)가 연결될 수 있다 → 포털에서 "누구의 안내인지" 선택.
- ⓐ 결정: 추가 확인으로 **생년월일 6자리**를 받을지 — 다온 의견: 받지 않음(소지 2단계로 충분, 생년월일도 주민번호 앞자리 대조가 되어 같은 쟁점).

## 2. 환자용 상담 안내(보낼 내용)

- 직원 기록은 그대로 두고, 보낼 때 **별도의 환자용 문서**를 만든다(같은 기록을 고치지 않는다).
- 진입: 연결 완료 카드 [📩 환자에게 보내기] → 작성 화면
  1. **고르기**: 기록을 항목별로(주소·소견·처치·처방·주의사항·다음 내원) + 기록 속 그림(치아 그림·치간칫솔 차트·상담자료 이미지) 체크.
  2. **환자용 문장**: 고른 항목으로 쉬운 말 초안 생성 → 직원이 수정(ⓑ).
  3. **미리보기**: 환자 휴대폰 화면 그대로.
  4. **보내기**: 문자 1통(+ 이후 카카오 알림톡).
- 내용 원칙: 진료 용어 풀어쓰기 · 내부 표시(`[이어서 상담 — …]`, 상담자 메모) 제외 · 처방은 제품·사용법(+ 재구매 링크, spec 036 B) ·
  용어 규칙 — 환자 화면 이름은 **"상담 안내"**(진료 기록·의무기록이라 부르지 않음).
- 데이터: 새 테이블 `patient_shares`(기록 id·환자·기관·환자용 본문·그림·처방·작성자·보낸 시각·**환자가 연 시각**). 직원 카드에 "환자가 확인했어요" 표시.
- 동의: 보내기 화면에서 **개인정보 제공 동의 확인 체크**(환자별 최초 1회, 기록 남김) — 현재 카드 경로의 자동 기록 제거.

## 3. 포털 — 한 건 보기 + 계속 초대

- 문자 링크 → (로그인 상태면 바로 / 아니면 §1 인증) → **그 안내 한 건**을 바로 보여준다.
- 안내 아래 **포털 넛징 카드**: "케어로그에서 이런 것도 할 수 있어요" — 지난 상담 안내 모아보기 · 다음 내원 알림 받기 · 처방 제품 재구매 ·
  (후속) 질문 남기기·상담 전 문진 등. [알림 켜기] [구글/카카오로 간편 로그인 연결].
- 포털 목록 = **보낸 안내만**(직원 기록 원문 노출 중단, ⓒ).
- 링크: 1회용 → **안내마다 링크, 유효기간 내 반복 열기 가능**(ⓓ), 만료 후엔 포털 로그인으로 자연스럽게 연결.
- 넛징 지점: 문자 문구 · 안내 하단 · 안내를 2번째 받을 때 "가입하면 모아볼 수 있어요" · 알림 허용 배너(기존) · 다음 안내 도착 푸시.
- 알림: 보낸 안내가 도착하면 푸시(가입·알림 허용 환자). 현재 끊긴 '새 상담 기록' 푸시는 안내 기준으로 대체.

## 4. 하지 않는 것(이번 범위)

- 환자가 직원 기록 원문을 보는 것 · 주민번호 입력 · 결제(spec 036 원칙).

## 5.5 확정 (2026-10-25 대표)

- ⓐ 생년월일 받지 않음 — **인증번호로만**.
- ⓑ AI 초안(1크레딧, `patient_share_draft`) → 직원 수정 · "고른 내용 그대로 넣기"도.
- ⓒ ★정정: 포털에서 **연결된 기록 전부 + 보낸 안내 모두** 보인다(직원 기록 원문 노출 유지). §3의 "보낸 안내만"은 철회.
  → 포털 = [받은 상담 안내](위) + [상담 기록](아래, 기존과 동일).
- ⓓ 30일 · ⓔ 다음 로그인 때 휴대폰 계정 전환 — 권고대로.

## 5.6 구현 (2026-10-25)

- 인증: `/p/[token]` = 로그인돼 있으면 바로 안내로, 아니면 `010-****-1234로 인증번호 받기` → 6자리 → 안내(`components/patient/invite-auth.tsx`).
  `/portal/login` = 휴대폰 번호 → 인증번호(이미 링크로 한 번 들어온 번호만). 주민번호 입력·대조 제거(`app/actions/patient-portal.ts`).
  계정 찾기 = 휴대폰 계정 → 없으면 이 번호 환자와 연결된 기존 계정(ⓔ 전환) → 없으면 새 계정.
- 보내기: 연결 완료 카드 [📩 환자에게 보내기] → `components/patients/share-composer.tsx`(① 고르기 — 기록 [라벨] 항목·그림·처방
  ② ✨ 쉬운 말 초안 / 고른 내용 그대로 → 편집 ③ 최초 동의 체크 → 문자) · 오른쪽 휴대폰 미리보기. 서버 `app/actions/patient-shares.ts`.
  문자: `[병원] ○○님, 오늘 상담 안내가 도착했어요. <링크>` · 가입·알림 허용 환자에겐 푸시도.
- 환자: `/portal/s/[id]` 안내 + 넛징 카드(`portal-nudge.tsx` — 모아보기·구글 간편 로그인·알림·재구매/다음 방문 "준비 중").
  `/portal/records` 위에 [받은 상담 안내](새 안내 배지), 아래 [상담 기록].
- 직원: 환자 페이지 카드 아래 "📩 보냄 · ✓ 환자가 확인했어요(시각·횟수)".
- 기존 '환자에게 전송'(카드 SMS 버튼)은 환자 페이지에서 내림. 남은 경로(이전 방식 임시저장·환자 정보 초대 버튼)도 주민번호 불필요·자동 동의 제거.
- 함께 고침: 환자 구글 로그인 복귀(`/auth/patient-callback`)가 미들웨어 공개 경로에 없어 비로그인 환자가 직원 로그인으로 튕기던 문제.
- 남은 것: 직원 겸 환자 연결(`linkMyPatientAccount`)은 아직 주민번호 사용(직원 내부 기능) · 기존 `rrn_hash` 삭제 · 카카오 알림톡 · 3단계.

## 6. 단계

| | 내용 |
|---|---|
| 1 | 인증 교체(주민번호 제거) + 포털 노출 = 보낸 안내만 + 링크 반복 열기 |
| 2 | 환자용 안내 작성 화면(고르기·초안·미리보기·동의) + `patient_shares` + 열람 표시 |
| 3 | 포털 넛징 카드 · 푸시 · 카카오 알림톡 |
