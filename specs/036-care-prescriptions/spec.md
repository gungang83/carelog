# spec 036 — 처방: 기록 템플릿(치간칫솔 차트 1호) + 재구매 링크

> 상태: **A단계 구현 (2026-10-22)** · B단계는 EO 쇼핑몰 상품 목록 대기.
> 대표 방향 확정 (2026-10-22, 같은 날 두 차례):
> 1. 처방은 사이즈·종류를 기록하는 템플릿(치간칫솔 차트 등)과 엮어 함께 내보낸다. 수량 기본 1, 직원 수정.
> 2. ★단순화: **Carelog 처방은 참고자료로만 쓴다.** 주문·결제·배송을 Carelog가 다루지 않는다.
>    - 병원(예미안)은 상담 기록의 처방 내용을 덴트웹 차트에 복붙하고, 실제로 팔지는 병원이 데스크에서 결정한다
>      (EO 판매 거래 기록은 병원이 평소대로 — Carelog가 대신 쓰지 않는다).
>    - 환자에게 상담 기록을 전달할 때, 그 제품이 **수완홀딩스 쇼핑몰에서 파는 물건이면 재구매 링크**를 붙인다.
>    - 이유: 처방→주문으로 가면 배송지·환자 결제·판매 주체(병원 매입 vs 판매처 직판)가 한꺼번에 생긴다.
>      링크로 넘기면 주문·결제·배송은 쇼핑몰(EO spec-114)이 이미 가진 흐름을 그대로 쓴다.

## 1. 구성

| 층 | 무엇 | 정본 |
|---|---|---|
| **기록 템플릿** | 상담 중 "어디에 무엇을" 기록. 1호 = 치간칫솔 사이즈 차트(치아 사이 26곳 × 사이즈) | Carelog (데이터 정의) |
| **처방 내용** | 템플릿 결과 + 처방 제품 — ★상담 기록 본문의 일부(이미지 + 복붙용 텍스트) | Carelog 상담 기록 |
| **재구매 링크** | 처방 제품 중 쇼핑몰 판매 상품이면 환자 화면에 [재구매] 링크 | 상품·주문은 EO 쇼핑몰 |

## 2. A단계 — 치간칫솔 사이즈 차트 (구현 완료)

- 진입: 상담보드 처방 섹션의 **[🦷 치간칫솔 사이즈 차트]** → 전체화면.
- 도식: 상하악 7-7(14개씩) 치열을 Carelog가 직접 그린 SVG — 2026-10-22부터 치아 도식 라이브러리(spec 037) 교합면. 치아 크기만큼 호 길이로 배치(어금니 겹침 없음),
  치아 사이 26곳 지점은 아치 바깥쪽(입술·볼 쪽)에 표시. ⚠️ 대표가 보여준 참고 화면(© 한국SOOD교육협회)은 쓰지 않는다.
- 조작: 위에서 사이즈 선택 → 치아 사이 점을 누르면 지정, 같은 사이즈로 다시 누르면 해제, [지우개]·[전체 지우기].
- [기록에 담기] → ①차트 PNG(범례·개소 포함)를 상담 기록에 이미지로 삽입 ②복붙용 텍스트 블록 삽입
  ```
  [치간칫솔 처방 — 2026-10-22 · 26곳]
  CPS 08 (14곳): 17-16, 16-15, …
  CPS 09 (9곳): …
  ```
  ③처방 칩 "치간 칫솔" 자동 선택.
- 사이즈 목록은 데이터(`lib/care-templates.ts` `DEFAULT_BRUSH_SIZES` — CPS 06·07·08·09·011, 색 지정).
  병원별 설정으로 옮길 수 있게 코드 분기 없음.
- 환자 전달: 차트·텍스트가 상담 기록 본문에 들어가므로 **기존 문자 링크(`/p/토큰`)로 그대로 전달**된다.

## 2.5 치간칫솔 라이브러리 (2026-10-22 — 대표 확정: 우선 하드코딩)

- 차트 상단에서 **제품군 선택**(큐라프록스 CPS prime / TePe Original) → 사이즈 팔레트에 **색·규격**(ISO·와이어 굵기·
  모 직경·통과 구경 중 있는 값) 표시, 사진 칸은 비어 있으면 색 원으로 대체. 한 환자에게 제품군을 섞어 지정 가능
  (선택 키 = `제품군id:사이즈id`), 범례·기록 텍스트에 제품군 표기.
- 데이터: `lib/care-templates.ts` `BRUSH_LINES` — ★EO 상품 모양(대표상품+옵션축 "사이즈"+옵션값)에 맞춘 **읽기 전용
  임시본**. Carelog에는 편집 화면을 두지 않는다(두 벌로 갈라지지 않게). 사이즈 이름은 나중에 EO 옵션값과 글자까지 맞춘다.
- **정본 이관**: 수완홀딩스가 EO에 치간칫솔 상품을 등록할 때(옵션축 "사이즈", 사이즈별 규격·사진) → Carelog는 출처만
  EO로 교체. 사진은 판매처 상품 사진을 쓴다(제조사 이미지 저작권).
- 규격 출처·검증 상태는 제품군별 `source`·사이즈별 `verified`에 기록:
  - CPS prime: 와이어·모 직경 = 판매처 공개 상세. 색은 06 파랑·07 빨강·09 노랑 확인, **08·011 색 미확인**(화면에 "확인 필요").
  - TePe Original: ISO 0–8·색·와이어 = TePe 전문가용 사이즈 가이드. **통과 구경(PHD)은 공식 자료 확인 전이라 비움.**

## 2.6 차트 3D 전환 · 사이즈별 그림 (2026-10-22 대표 지시)

- **2D·3D 전환**: 차트 상단 [2D | 3D] — 쓸 때마다 선택(마지막 선택 기억). 3D에선 치아 사이 26곳 점이 입체 위치(협측 치경부 1/3)에 떠서
  돌려 보며 눌러 지정, 2D와 지정 상태 공유. [기록에 담기] = 지금 3D 화면 + 범례를 한 장으로 합친 PNG + 같은 텍스트 블록.
- **사이즈별 그림**: 팔레트·범례(기록 이미지 포함)에 사이즈 그림 — `components/care/brush-illustration.tsx`, Carelog 자체 그림
  (손잡이 = 사이즈 색, 와이어 굵기·모 직경 = 규격 비율). 모 직경 미확인 사이즈(TePe)는 와이어 굵기로 근사한 그림.
- **실제 사진**: `BrushSize.imageUrl`에 넣으면 팔레트가 사진으로 바뀐다. ⏳ 사진 확보 대기 — 판매처(수완) 상품 사진을 대표가 전달
  (제조사 이미지 직접 사용 금지 원칙 유지). 받으면 `public/brushes/<제품군>/<사이즈>.jpg`로 넣는다.

## 3. B단계 — 재구매 링크 (EO 대기)

- EO에서 **쇼핑몰(수완홀딩스 등) 판매 상품 목록**을 받는다 — 상품명·옵션(사이즈)·이미지·**상품 페이지 URL**.
- 처방 섹션의 하드코딩 칩 4개를 이 목록 기반 선택으로 교체. 치간칫솔 차트의 사이즈는 쇼핑몰 상품의 사이즈
  옵션(EO spec-120 옵션축)과 연결.
- 환자 화면(`/p/토큰`)의 상담 기록 아래 "처방 제품" 카드 — 이미지·이름·[재구매] 링크(쇼핑몰 상품 페이지).
  주문·결제·배송은 전부 쇼핑몰에서.
- 판매처가 여럿이 되어도(수완 외) 링크만 달라지므로 구조 불변 — 응답을 처음부터 판매처(쇼핑몰) 배열로 받는다.

EO 요청(마르코 — 커머스 오너):
```
GET /api/gateway/shop-products?institution_id=...
→ { shops: [ { workspace_id, name, shop_url,
       products: [{ product_id, name, brand, image_url, product_url,
                    option_types: [{ name, values[] }] }] } ] }
```
- 예미안과 연결된 쇼핑몰(1차: 수완홀딩스)의 공개 판매 상품만. 가격은 표시용(선택).

**EO 회신 (카드 #1993 마르코, 2026-10-22)** — 구현은 테오(#1994, spec-114 아래 · 읽기 전용):
- ⑴ `product_url` 있음 — 옵션축 상품이면 대표상품(product) 경로.
- ⑵ spec-120(대표상품+옵션축+SKU) **구현됨** → 치간칫솔 사이즈 = 상품 옵션값으로 맞출 수 있다.
- ⑶ "연결된 쇼핑몰" = EO `commerce_buyer_link`. 가드 2개: **연결된(linked) 몰만 · 공개(public) 몰만**.
- 확인 중: `image_url`이 서명 URL인지(테오 ⑥). ★서명 URL이면 Carelog는 저장하지 않고 화면을 그릴 때마다 새로 받는다
  (기공지 ⓒ와 같은 원칙 — 만료되는 링크를 기록·DB에 남기지 않음).

**게이트웨이 배포 (카드 #1993 개정판, EO main@c116a3a2 · 설명: EO specs/114-eo-commerce-platform/carelog-shop-link.md)**
- `GET /api/gateway/shop-products` 응답에 `price_from`, `skus[{item_id, code, option_values, price}]`도 포함.
- `image_url` = **공개 버킷(만료 없음)** — 위 우려 해소, 환자 문자에 넣어도 깨지지 않는다.
- ★`option_values`의 키는 `option_types[].name`과 **정확히 일치**(공백·대소문자까지) — 사이즈 차트 결과를 SKU에 꽂을 때 이 키로 매칭.
- ⛔처방 ≠ 판매 — 처방 건수로 재고를 깎는 배선을 만들지 않는다(EO 확인).
- ⏸ **지금은 `shops: []`** — 수완홀딩스 몰이 `members`(회원 전용)라 공개 가드에 걸림. 고장 아님.
  몰 공개는 **대표가 미룸(㈐)**. 회원 전용 몰은 비회원 환자를 로그인으로 돌려보내고, 몰 가격이 한 벌(B2B 납품가)이라
  공개하면 도매가·치과용 품목이 그대로 노출된다.
  → 재구매 링크가 필요해지는 시점에 ㈎ 수완 몰 공개 / ㈏ **환자용 몰 신설(소매가·환자 품목만, EO 코드 변경 0)** 중 선택.
  다온 의견: ㈏.
- **B단계는 그때까지 보류.** 처방·사이즈 차트는 링크 없이 먼저 쓴다.

## 3.5 재구매처 = 예미안 덴탈샵(환자 전용 폐쇄몰) (2026-10-22 대표 설명)

- 사업 구조: 수완홀딩스 → 예미안 B2B 납품 / 수완 '닥터제이스' = 공개몰(스마트스토어·유튜브) /
  예미안 **'덴탈샵' = 예미안 환자 전용 폐쇄몰**(현재 카페24, EO로 이전 계획 — 내부 공표 완료).
- ★큐라프록스 등 다수 제품은 **공개몰 판매 불가, 폐쇄몰만 가능** → 환자 재구매 링크는 덴탈샵 상품을 가리켜야 한다.
- 현재 환자 인증 = **수동**(직원이 차트와 일일이 대조).
- ★Carelog의 역할: 환자가 이미 Carelog 링크·휴대폰 인증으로 자기 상담 기록을 보므로, Carelog가 "예미안 환자 확인"을
  증명해 덴탈샵에 입장시킬 수 있다(EO→Carelog SSO의 역방향) → 수동 대조를 대체.
- 경과 조치(EO 이전 전): 환자 화면에서 카페24 덴탈샵으로 링크(인증은 지금처럼 수동). 마르코 논의 카드 발송(2026-10-22).
- **마르코 회신 #2001 (2026-10-22)**: ④ 폐쇄몰 전용 품목 가드만 진행(테오 #2000 — `inv_item.closed_shop_only`, 제한 품목이 공개몰에 진열되지 않게 서버에서 거부), 나머지는 보류(덴탈샵 이전 본체 포함).
  공개몰은 비회원 주문까지 되지만 결제가 막혀 있음 → PG는 모건 트랙 · 회원 이관은 솔론 선행 ·
  경과 조치(카페24 덴탈샵 링크)는 다온 재량 → 대표가 덴탈샵 주소를 주면 붙인다.

## 4. 하지 않는 것 (대표 확정)

- Carelog → EO 판매 거래 기록 · 재고 차감 · 주문 생성 · 환자 결제 · 배송지 수집.
