# spec 034 — 상담 품질 평가 (체크리스트 대조) · 🧪 테스트중

> 상태: **v1 구현 (2026-10-19).** 기획공장(이정숙 대표) 협업 — 체크리스트 대조 평가.
> 대표 확정 2026-10-19: ①음성 어조는 사람이 녹음 듣고 **수동 평가**로 보완하며 시작
> ②점수화는 시뮬레이션 돌려보며 정교화(기획공장 역할 큼) ③권한은 **일단 슈퍼어드민만**,
> 단 상담자 당사자·기획공장측에 언제든 열람·평가 권한 줄 수 있게 기능 구현 ④'테스트중' 표시.
> 기획 초안: `specs/000-backlog/consult-eval-checklist.md`

## 1. 핵심 설계

- **하이브리드 항목 타입**: 템플릿 항목마다 `type: 'auto' | 'manual'`
  - `auto` = AI가 상담 기록 본문(텍스트)에서 판정 — 내용·언어적 태도(공감 표현, 쉬운 설명 등)
  - `manual` = 사람이 녹음을 직접 듣고 판정 — 어조·경청·끼어들기 등 음성적 측면 (Phase 2 자동화 전까지 수동 보완)
- **판정값**: `met`(충족) | `partial`(부분) | `unmet`(미충족) | `na`(해당없음) + **근거 인용 필수**(신뢰의 핵심) + 코멘트
- **점수 = 실험 필드**: 항목 `weight`(배점) 가중 합을 계산하되 항상 **'실험' 라벨**과 함께 표시.
  시뮬레이션을 돌려가며 기획공장과 배점·기준을 정교화한다 — 점수 자체를 약속하지 않는다.
- **포지셔닝**: 코칭 보조 도구. 인사평가 근거 아님(과약속 금지 — 현장 반발 방지).

## 2. 데이터 (migration `20261019000001_consult_eval.sql`)

| 테이블 | 내용 |
|---|---|
| `eval_templates` | 체크리스트. **3층 제공·관리 모델**(대표 확정 2026-10-19): 배포 범위=`institution_id`(NULL=전 기관 공통/지정=워크스페이스 전용) × 제공 주체=`provider`(NULL=케어로그 기본/'기획공장' 등=컨설팅 파트너, migration `20261019000002`). `items` jsonb `[{id,label,guide,type,weight}]`. 템플릿 탭에서 생성(기존 복제 포함)·편집·활성/삭제 |
| `eval_runs` | 상담 1건 평가 결과. `ai_result`/`manual_result` jsonb `[{item_id,verdict,evidence,comment}]`, `score`(실험), `summary`(AI 총평) |
| `eval_grants` | **권한 개방 대비**: `grantee_email` + `can_view`/`can_evaluate`. v1은 비어 있음(슈퍼어드민만) — 당사자·기획공장 개방 시 행 추가만 하면 됨 |

RLS: 3테이블 enable + 정책 0 — service_role(슈퍼어드민 서버 액션)만 접근. 권한 개방 시 grants 기반 정책 추가.

## 3. 배선

- `app/actions/consult-eval.ts` — 슈퍼어드민 가드(+`hasEvalGrant()` future-proof 헬퍼), 템플릿 CRUD,
  `runEvaluation(consultationId, templateId)`: 본문 텍스트화 → Claude(claude-sonnet-4-6)가 auto 항목 strict JSON 판정
  → eval_runs 저장 + 실험 점수 계산. `saveManualResult(runId, items)` = 수동 항목 입력. grants 관리 액션.
- `/admin/eval` + `components/admin/eval-manager.tsx` — 기관 선택 → 최근 상담 → [AI 평가 실행] → 결과(verdict 칩+근거+수동 폼+실험 점수), 템플릿 편집, 권한 관리. 🧪 테스트중 배지 상시.
- 크레딧: `consult_eval = 3` (비차단 기록 — deductCredit 패턴).
- 기본 템플릿: 첫 진입 시 자동 씨드 — auto 8(주소(主訴) 확인·공감 표현·쉬운 설명·옵션 2개 이상·비용 안내·주의사항 고지·질문 응대·다음 단계 안내) + manual 3(어조·경청/끼어들기·마무리 인사).

## 4. 전사 원문 보관 (2026-10-20 보강 — 첫 실측 "판정불가 다수" 직후 대표 확정)

- ✅ **원문 보관 시작**: 파이프라인(음성→전사 원문→요약)에서 폐기되던 원문을 `consultation_transcripts`에 보관
  (migration `20261019000003`). 저장 경로 전부 배선: 보드·오버레이(클라 전사), 서버 워커(transcript_mode
  replace/append — 이어서 상담은 append, 재요약은 replace), 청크·비교 모드 포함.
- **평가는 원문 우선**: 원문 있으면 원문 기반(미발화=unmet 판정 가능, 오타는 의미 중심 감안 지시),
  없으면 요약 폴백(na 유도). `eval_runs.basis`로 기록, UI에 '원문 기반/요약 기반' 뱃지.
- **기존 기록 복구 경로**: 음성 보관된 기록은 평가 목록 [원문 확보] → `transcript_only` job(본문 불변,
  전사만 1크레딧) → 워커가 원문 저장 → 재평가.
- **민감도**: 원문은 대화 전문 — RLS 정책 0(서버 전용), 평가 화면에도 원문 자체는 표시하지 않음(근거 인용만).
- 남은 한계: 음성 어조 자동 평가는 Phase 2(Soniox 화자분리 등) — 그때까지 manual 항목으로 수동 보완.
  화자 분리 없음 → 원장/환자 발화 구분은 문맥 추정.
