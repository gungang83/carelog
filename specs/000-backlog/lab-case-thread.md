# 기공 케이스 대화방 — 논의 기록 (2026-10-30 · 대표 ↔ 다온)

> 상태: **논의 중.** 대표 확정분과 다온 권고를 구분해 남긴다. 확정되면 EO spec 138 확장(EO 소관)과
> Carelog 쪽 변경을 각각 스펙으로 옮긴다. 경계·계약 오너 = 헤임달, EO 구현 = 테오·마르코.

## 0. 요청 (대표)

- 기공지를 보내면 그 케이스를 두고 치과·기공소가 글·댓글·링크·사진을 남기며 진행 → 케이스 이력이 남는다.
- 케이스 링크를 복사해 카톡방 등에 올릴 수 있게.

## 1. 현황 (EO spec 138 읽기 대조, 2026-10-30)

- 기공소 = EO 독립 워크스페이스(`/lab-work`, 기공소 직원 = EO 멤버). 치과 워크스페이스 의뢰가 기공소 워크스페이스로 **복제**(`dental-lab-mirror.ts`, `mirror_of`).
- "물어보기" 스레드 설계 있음: `dental_lab_order_events`(type=comment, actor_side clinic|lab, append-only) — 양쪽 이벤트에 각각 기록.
  **기공소 쪽 쓰기만 구현**, 치과 쪽 쓰기·화면 없음. 기공소 사진 업로드 없음(치과 사진도 이름만 표시).
- EO→Carelog 상태 알림(§2-3) 2차 보류. 로그인 없이 여는 건별 링크·카톡 공유 없음.

## 2. 대표 확정

| # | 내용 |
|---|---|
| 1 | **카톡 미리보기에 환자 이름 넣는다.** 내부 논의 창이므로 어떤 케이스인지 명확히. |
| 2 | **EO 계정 없는 기공소 = EO 가입 유도.** 손님 인증 등 별도 경로 만들지 않는다. |

## 3. 대표 제기 → 다온 권고 (확정 대기)

| # | 질문 | 다온 권고 |
|---|---|---|
| A | 접수 후엔 EO에서 전부 처리? | **예.** Carelog = 기공지 작성(양식·치식·사진·그림), **접수 이후 케이스 = EO 정본**(치과·기공소 둘 다 EO 멤버, 원장·청구도 EO). Carelog 기공지 목록은 "EO에서 케이스 열기"로 연결. |
| B | 그림 덧붙이기는 Carelog 엔진이라 복잡? | 1차는 **이미 있는 길 재사용**: 치과가 그림을 더하고 싶으면 Carelog 기공지 [수정·첨부] → revision 재전송(§3.9, EO가 🔄 수정으로 받음). EO 대화방은 글·사진·링크. 기공소 쪽 그리기·EO 안 그리기 도구는 2차(Carelog 주석 도구 이식 검토). |
| C | 양쪽 워크스페이스 복제 = 에러 증가? | 타당한 우려. 대화는 **한 레코드를 양쪽이 같이 보는 구조**(공유 행 + 접근 권한)가 복제보다 어긋날 여지가 적다. 다만 EO 기존 설계(mirror) 변경이라 **헤임달·테오 판단 안건**으로 올린다. |
| D | 대화 = 치과 소유? 공유? | **공유 기록.** 재제작·책임·청구 다툼의 근거라 양쪽이 같은 내용을 봐야 한다. 규칙: 수정·삭제 없이 덧붙이기만(정정은 새 글), 환자 식별 항목은 기존 share 정책(치과 설정) 따름. 거래 종료 후 기공소 보관 범위는 **솔론** 확인. |
| E | 링크 = Carelog? EO? | **EO 링크.** 케이스 정본이 EO이고 양쪽 다 EO 로그인 → 하나의 링크로 같은 케이스. 미리보기(OG)는 EO가 렌더 — 제목 예: `[예미안치과→지플란트] 홍길동 · #46 크라운 · 납기 11/3`. Carelog는 [🔗 링크 복사]만. |

⚠️ 미리보기 제목은 **링크를 가진 누구에게나 보인다**(카톡 서버가 로그인 없이 가져가야 미리보기가 뜸). 본문·사진은 로그인 뒤. 대표 확정 1에 따른 수용 범위 = 미리보기 제목까지.

## 3.5 경계 재정리 (2026-10-30 대표 — "작성은 Carelog, 거래는 EO")

- 대표: 기공지 **작성·그리기는 Carelog**(임상·상담·환자 정보와 맞닿음), **거래 데이터는 EO**.
  → 작성 화면 전체 EO 이식(다온 앞선 ③안)은 하지 않는다. 이식 대상은 **그림 도구만**.
- 역할: Carelog = 기공지 작성·수정(접수 후 수정도 Carelog → revision 재전송, 기존 계약) /
  EO = 접수 이후 케이스(상태·대화·청구·링크). EO 케이스 화면 [✏️ 기공지 수정] → Carelog 작성 화면(SSO 링크).
- 공용 부품 = EO 대화방에서 사진 위에 표시하는 `ImageAnnotator`(510줄, React만 의존 — DB·서버 무관).
  1차 = EO에 **복사**(원본 Carelog 표기), 두 앱이 계속 함께 고치게 되면 공용 패키지로 승격.
  각 앱 빌드에 포함되므로 로딩은 자기 기능과 동일(원격 호출·iframe 아님). 3D 치아 모형은 작성 화면용이라 Carelog에만.

## 4. 범위 초안 (A~E 권고대로일 때)

- **EO (spec 138 확장 · 테오·마르코)**: 치과 쪽 대화 쓰기·화면 · 대화 사진 첨부(양쪽) · 건별 링크 + OG 미리보기(환자명 포함) · 새 글 알림 · (안건) 복제 → 공유 행.
- **Carelog**: 기공지 목록·환자 페이지에 [EO에서 케이스 열기]·[🔗 링크 복사] · EO→Carelog 상태 표시(§2-3, 접수·제작중·완료 뱃지).
