## 1. 왜 지금 정해야 하나

- Carelog가 환자에게 **상담 안내**를 보내기 시작했다(spec 038). 지금은 문자(솔라피)로 나가고, 카카오 알림톡은 코드 준비 완료 — 채널·템플릿만 있으면 켜진다.
- 그런데 계정·채널을 **누구 명의로, 몇 개로, 누가 관리하며, 비용을 누가 내는지**가 정해지지 않았다. 카카오 템플릿은 승인 후 **수정 불가**, 비즈니스 인증은 **사업자 1개 명의**라서 한 번 잘못 잡으면 되돌리기 비싸다(PLAYBOOK §5 "되돌릴 수 있게").
- EO도 같은 솔라피·같은 번호로 문자를 보내고 있다(근로계약서 서명 인증코드). → **제품 공통 자산**이라 Carelog 단독 결정이 아니다.

## 4. 결정 후 할 일 (참고 — spec 038 §7 상세)

1. 카카오비즈니스 통합 계정 → 채널 개설 → 비즈니스 채널 인증(ⓑ 사업자 서류, 영업일 1~3일).
2. 채널 공개 ON · 관리자 추가 인증 · 고객센터 정보 입력 → 솔라피 채널 연동(pfId).
3. 알림톡 템플릿 등록(원고 = spec 038 §7, 도메인 ⓖ 반영) → 카카오 검수(영업일 1~3일).
4. 회사 발신번호(ⓒ) 솔라피 등록 → 템플릿 대체 발송 번호로 지정 + 각 제품 `SOLAPI_SENDER_PHONE` 교체.
5. 다온: Carelog env 2개 + 기본 발신번호 교체 → 재배포 → 대표 번호로 시험 발송. EO 쪽 적용은 오너가 테오와.

## 7. 확정 — 계정 구조 (헤임달 #2092 · 2026-10-26 대표 결정)

- **수완홀딩스 명의 솔라피 새 계정 1개를 EO·Carelog가 공유.** 대표 개인 계정은 이관 후 해지.
- **제품별 messageId 저장 규칙(헤임달 계약)**: 웹훅은 계정 단위라 등록 URL이 모든 제품의 결과를 받는다 →
  각 제품은 **자기가 보낸 messageId의 결과만 저장하고 나머지는 버린다.** Carelog는 지금 수신 경로가 없어 해당 없음 —
  나중에 발송 결과 수신을 붙이면 발송 시 messageId를 저장하고 이 규칙을 따른다.
- 알림톡 템플릿 등록은 계속 보류(솔론 판단 전 · 승인 후 수정 불가).
- Carelog 전환 작업(#2092 ①②) — ⏸ 대표 준비 대기: 새 계정·회사 발신번호 준비.
  ★다온(원격 에이전트)은 솔라피·Vercel 콘솔에 로그인할 수 없다 → 키 발급과 Carelog Vercel env 교체는 대표(또는 테오)가 하고,
  다온은 재배포 확인·시험 발송 안내·기록을 맡는다.
  1. 솔라피(수완 계정) › API Key 관리 › 새 키 발급(Carelog 전용 이름) — 회사 발신번호 등록 완료 확인
  2. Vercel › carelog 프로젝트 › Settings › Environment Variables(Production) — `SOLAPI_API_KEY` · `SOLAPI_API_SECRET` · `SOLAPI_SENDER_PHONE`(숫자만) 교체
  3. Deployments › 최신 배포 › Redeploy(환경변수는 재배포해야 반영)
  4. 시험: ① 환자 안내(시험 환자 카드 › 📩 환자에게 보내기) ② 링크 인증번호 ③ 포털 로그인 인증번호 — 세 문자 모두 새 번호로 오는지

## 8. 솔라피 콘솔 확인 (2026-10-26 대표 화면)

- **조직은 1개**("송정현님의 계정") — 사업자정보 = 주식회사 수완홀딩스로 이미 등록. → **새 계정 불필요, 이 조직을 수완 공용으로 정리**(이름 "수완홀딩스"로 변경 ✅).
  ★정정(헤임달 #2092 회신 ②, 대표 확정): **콘솔 멤버는 대표 1인 유지.** 발송 내역에 환자 이름 원문이 보이므로 수완 쪽 인원(직원 등)은 멤버로 넣지 않는다.
  두 번째 관리자(분실 대비)는 솔론이 '환자정보 열람 자격' 기준을 정한 뒤 그 기준에 맞는 사람으로.
- **워크스페이스**(콘솔 설명 원문 요약): 조직 안에서 멤버와 데이터를 나눠 쓰는 단위.
  - 통계·인사이트 = 그 워크스페이스에서 보낸 발송만 집계 · **API Key는 만들 때 고른 워크스페이스에 묶이고 그 키의 발송은 그 워크스페이스로 집계** · CRM 데이터 분리.
  - ★**잔액·발신번호·발송 내역은 워크스페이스와 관계없이 조직 전체 공통.** 웹훅 분리 여부는 설명에 없음 → 조직 단위로 가정(#2092 messageId 규칙 유지).
  - → 제품별 **키·사용량 통계 분리**(모건 ⓘ 비용 배분에 유용)는 되지만, **발송 내역(환자 이름 포함 문자 원문)은 조직 멤버 모두에게 보인다** → 콘솔 멤버 = 대표 1인(위 정정).
- 다온 제안: **"Carelog" 워크스페이스**를 만들고 그 안에서 Carelog 전용 키 발급. EO 워크스페이스는 테오·헤임달 판단.

## 9. 확정 — 워크스페이스 분리 · 공용 키 폐기 (헤임달 #2092 회신 · 2026-10-28 대표 확정)

- ① EO도 'EO' 워크스페이스 + 전용 새 키. **양쪽 교체가 끝나면 예전 공용 키 폐기(대표).** 공용 키가 두 제품 Vercel에 다 있었으므로 폐기까지 가야 실제 분리.
