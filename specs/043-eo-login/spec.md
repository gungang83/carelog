# spec 043 — EO 계정으로 케어로그 로그인 (로그인 통합 ①·②)

- 상태: ①② 배포·대표 확인 ✅(2026-11-28 "바로 들어가지고 로그아웃도 잘 돼") · §7 같이 쓰는 PC 처리 배포
- 요청(2026-11-28 대표): 로그인 통합 개념 설명 → "권유대로 하자"(① EO로 로그인부터)
- 앞선 것: spec 042(carelog.eo.ai.kr) · 카드 235(EO→케어로그 SSO 버튼, 계약 EO spec-016)

## 1. 개념 — DB를 합치지 않고 '신뢰 관계'로
- 두 앱은 사람 명단(DB)·출입증(세션 쿠키)이 각자. 통합 = "EO가 서명한 사람이면 케어로그가 출입증을 내준다".
- 서명 = 두 앱만 아는 비밀 열쇠 `CARELOG_SSO_SECRET`(HS256, 60초 유효). 케어로그 `/api/auth/sso`가 검증 → 계정·병원 연결 → 로그인(카드 235부터 있던 것).
- DB(로그인 시스템) 하나로 합치기는 안 함 — RLS 전면 재작성 + EO 로그인 장애가 진료실까지 번짐.

## 2. 발견 — EO 쿠키가 이미 케어로그 주소에 온다
- EO(Auth.js)는 로그인 쿠키를 `.eo.ai.kr` 전체에 둔다(EO #2681, 2026-11-18 — eo·buddy 공유). → `carelog.eo.ai.kr`에도 브라우저가 보냄.
- 그래서 **EO 코드 변경 없이** ①·② 가능. 케어로그는 그 쿠키를 해독하지 않는다(EO 열쇠 없음·두지 않음) — EO 기존 창구에 그대로 건네 "이 사람 누구?"를 물을 뿐.

## 3. 흐름
```
[EO 계정으로 로그인] 또는 자동(아래)
  → GET /api/auth/eo-login?next=/records
      EO 세션 쿠키만 골라(authjs.session-token[.n]) → POST {EO_APP_URL}/api/carelog/sso-token  (EO 기존 창구, 서버-서버)
      ← { token }  (EO 서명 60초 증명서)
      → /api/auth/sso?token=…  (기존 검증·계정 연결·로그인) → 돌아갈 화면(carelog_sso_next 쿠키, 5분)
  실패: 401 → /login?eo=signin · 403 → eo=not_linked · 400 → eo=no_workspace · 그 외 → eo=fail (자동 반복 없음)
```
- **자동(②)**: 미들웨어 — 케어로그 로그인 없음 + EO 세션 쿠키 있음 + 첫 화면/보호 화면이면 곧장 eo-login. 로그인 화면 자체가 안 보임.
  - 제외: `/login` 직접(수동 선택 존중) · 환자 화면(/p·/portal 등 공개 경로) · 로그아웃 직후(`carelog_no_eo_auto` 쿠키, 브라우저 닫거나 다시 로그인하면 풀림).
- 로그인 화면: 맨 위 [EO 계정으로 로그인] + 실패 이유 안내(EO 열기 링크). 아래는 기존 이메일·구글.

## 4. 안전
- 케어로그가 EO로 보내는 것: EO 세션 쿠키만(케어로그 자체 sb-* 쿠키는 안 보냄 — 로컬 확인). 값은 저장·로그 안 함. 목적지는 `EO_APP_URL`(eo.ai.kr) 고정.
- 돌아갈 주소는 사이트 내부 경로만(`safeNextPath` — `//`·`https://`·`/login`·`/api/` 거부).
- 옛 주소(carelog-tau.vercel.app)는 EO 쿠키가 안 옴 → 자동 없음(어차피 새 주소로 넘어감).

## 5. 남은 것
- EO에 알림 카드(쓰기 요청 아님) — 전달 완료(2026-11-28), 회신 대기. `specs/000-backlog/card-eo-login-relay.md`.

## 6. 확인
- 로컬(가짜 EO 서버): 쿠키 없음→eo=signin · 정상→sso?token + 돌아갈 화면 쿠키 · 403→not_linked · 만료→signin · `//evil.com`→/ ·
  자동: `/`·`/records?x=1` → eo-login(next 유지), 로그아웃 표시 있으면 기존 로그인 화면, EO 쿠키 없으면 /about, `/login`은 자동 안 함. EO로 간 쿠키는 EO 세션 쿠키 하나뿐.
- 운영(대표): EO 로그인 상태로 carelog.eo.ai.kr 열기 → 로그인 화면 없이 들어가는지 · 로그아웃 후 다시 안 들어가지는지.

## 7. 같이 쓰는 PC (2026-11-28 대표)
> "가끔 '지금 누구예요' 물어보지 마. '현재 누구로 로그인돼 있다'가 보이는 것만으로 괜찮아. UX·로딩 영향 주지 말자.
>  같이 쓰는 PC에서 케어로그는 공용 계정으로 로그인해 놓고, 개인이 EO 로그인해서 쓰다가 EO 로그아웃 또는 브라우저 종료하는 경우는?"

- 결정: 전면 '같이 로그아웃'(③)은 안 함(체어 화면 보호). EO에 주기적으로 묻기(누구인지 확인)도 안 함.
- **공용 계정**(케어로그 이메일·구글 로그인): EO 로그인·로그아웃과 **무관** — 개인이 같은 PC에서 EO를 써도 공용 계정 그대로(자동 로그인은 케어로그 로그인이 없을 때만).
- **EO로 들어온 개인 로그인**(EO [케어로그] 버튼·EO 계정으로 로그인·자동): 표시 쿠키 `carelog_via_eo`(=케어로그 user id, 60일).
  EO 로그인 쿠키가 사라진 뒤 **케어로그 화면을 새로 열면**(새로고침·새 탭·주소 입력 = `sec-fetch-dest: document`) 이 브라우저의 케어로그 로그인만 끝냄(`signOut scope local` — 그 사람의 다른 기기는 그대로)
  → /login "EO에서 로그아웃해서 개인 로그인도 끝냈어요" + 자동 로그인 잠시 멈춤(다음 사람이 공용/EO로 골라 로그인).
  - 안 하는 때: 화면 안 이동·미리 받기(RSC)·저장·녹음 업로드(POST)·API·환자 화면 → 상담·녹음 중엔 절대 끊기지 않음.
  - 네트워크 호출 0(쿠키 유무만 봄) — 로딩 영향 없음.
  - 표시가 다른 계정 것이면(공용 계정으로 바꿔 로그인) 무시하고 지움 → 공용 계정 보호.
- **브라우저 종료**: EO 로그인은 60일 유지(EO `session.maxAge`)라 브라우저를 닫아도 EO·케어로그 모두 로그아웃되지 않음.
  같이 쓰는 PC는 'EO 로그아웃'이 끝내는 방법. 브라우저 종료로도 끝내려면 EO 쪽 결정(세션 쿠키를 브라우저 세션으로 등) 필요 — 대표 판단.
- **지금 누구로 로그인**: 헤더 프로필 옆에 이름(넓은 화면) + EO로 들어왔으면 `EO` 표시. 프로필 메뉴에 "EO 계정으로 로그인 · EO 로그아웃 시 함께 로그아웃" / "케어로그 계정으로 로그인". 이름은 작성자 표시명 우선.
- 확인(로컬, 가짜 Supabase): 개인+EO 로그아웃+화면 열기 → 로그아웃·/login · EO 로그인 중 → 그대로 · 공용 → 그대로 · 다른 계정 표시 → 무시·지움 · RSC 이동·POST·환자 화면 → 그대로.
